Overview

01System Architecture

A three-tier single-page application. A Vue 3 client renders the UI and holds all view state; a Python FastAPI service exposes a REST API and performs all filtering and aggregation in memory; seven JSON files act as the data source, loaded once at startup. There is no database.

Request Lifecycle

03Data Flow

A single read request — e.g. loading the Dashboard — travels through these stages. State stays one-directional: raw API data lands in refs, and derived values are computed properties.

1

User interactionFrontend

A view mounts or the user changes a filter in FilterBar.vue. The shared useFilters composable (a singleton) holds the four filter refs: Time Period, Warehouse, Category, Order Status.

2

Build the requestFrontend

getCurrentFilters() maps state into a params object; api.js drops any 'all' values and serializes the rest into a query string with URLSearchParams.

3

HTTP callFrontend

Axios issues GET http://localhost:8001/api/dashboard/summary?.... CORS (open in dev) lets the :3000 origin reach the :8001 service.

4

Route & filterBackend

FastAPI matches the route and reads optional query params. apply_filters() narrows warehouse/category/status; filter_by_month() resolves a month or quarter (Q1-2025) against in-memory lists.

5

Aggregate & validateBackend

The endpoint computes totals (inventory value, low-stock count, pending orders). Results are validated against Pydantic response_model schemas before serialization.

6

Read source dataData

All filtering reads from the lists loaded by mock_data.py at startup from server/data/*.json. Reads only — nothing is written back.

7

RenderFrontend

JSON returns to the awaiting Axios call. The view stores it in refs (allOrders, inventoryItems); computed properties derive charts and KPIs, and Vue reactively re-renders.

Conventions

05Key Patterns & Concerns

Shared Filter System

Four global filters drive every data view via a singleton composable:

Time Period Warehouse Category Order Status

State & Reactivity

  • Raw API data lives in refs; derived data in computed properties.
  • One-way flow: props down, events up.
  • Charts are custom SVG; layouts use CSS Grid.

Demo Constraints

  • No database — data resets on restart.
  • Writes (tasks, POs) are in-memory only.
  • No auth; CORS open to all origins.

Run Locally

  • Backend: cd server && uv run python main.py
  • Frontend: cd client && npm run dev
  • API docs: localhost:8001/docs
